<threat>
  <id>T-03-01</id>
  <description>Disabled Row-Level Security via Invalid SQL Syntax: O comando malformado `alter table enable row level security;` sem nome de tabela falha na execução da migração ou deixa tabelas multi-tenant (`workspaces`, `messages`, `management_objects`) sem RLS ativo.</description>
  <mitigation>Corrigir todas as migrações existentes (`001`, `002`, `003`) e criar a `004` com `alter table <table_name> enable row level security;` explícito para cada tabela, validado continuamente pelo teste automatizado `tests/core/supabase-migrations-rls.test.ts`.</mitigation>
  <asvs_level>Level 1</asvs_level>
</threat>
<threat>
  <id>T-03-02</id>
  <description>Cross-Tenant Data Leakage in Storage Layer: Consultas de persistência ou histórico executadas sem filtro de `tenant_id` / `workspace_id` podem retornar valores ou evidências de outro cliente.</description>
  <mitigation>A função `assertTenantScope(tenantId)` em `src/packages/core/supabase-storage.ts` valida obrigatoriamente o `tenant_id` antes de qualquer operação de leitura ou escrita e aplica filtro `.eq('tenant_id', tenantId)` em todas as tabelas.</mitigation>
  <asvs_level>Level 1</asvs_level>
</threat>
</threat_model>
